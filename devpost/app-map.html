A three-stop reference route

This is a reference route, not a claim that the learner completed a hands-on tour. Snapshot: source commit 03f6d9d plus preparation changes; source can evolve.

  1. src/app.js — search $("compare").addEventListener. It snapshots the inputs, invokes comparison and clears old decisions. Input listeners call invalidate so edited inputs cannot leave an exportable stale review.
  2. src/engine.js — parseDocument, retrieve and compare preserve source slices, locate candidates and decide which evidence needs verification. changedSpan only supplies visual text highlighting.
  3. src/app.js — evidenceCard renders literal quotations; renderDetail records a human decision; the export button downloads sources, results and notes.

Source matching and uncertainty

src/engine.js: retrieve has lexical thresholds; misleading detects a limited set of example phrases. Add independently authored cases in tests/fixtures.js before making broad claims.

Appearance and layout

src/style.css: color variables at the top; media queries for tablet and mobile. index.html contains page structure and input help.

Demonstration documents

src/demo.js contains all synthetic reference text and procedure steps. Keep them clearly labeled synthetic in future recordings.

Saved procedure and export

src/app.js: storageKey, Save/Forget handlers and the Export handler. Documents stay in tab memory; explicit Save stores only the procedure.

A practice to reuse

The requirement “show exact evidence” became a check in tests/engine.test.js: every quote must equal source.slice(start, end), with correct line numbers. This checks quotation integrity separately from interpretation. The cross-reference and hypothetical misses retained in docs/evaluation.md show why exact quotes alone do not prove a correct conclusion.

On another project, identify the property that must always hold, test it directly, and separately record what that test cannot establish.
